# ttabs

[English](./README.md) · Українська

Групує вкладки Chrome за задачами Jira — з командного рядка — і слідкує, щоб
назва кожної групи відповідала статусу задачі:

```
REQ|ACME-218   DEV|ACME-253   REV|ACME-254   QA|ACME-261   HOLD|ACME-266
```

Тоді одне вікно вміщає кілька задач поруч, і їхні вкладки не змішуються, а сама
смуга вкладок працює ще й як дошка. Керують цим скрипти: команда «почати роботу
над задачею» відкриває групу з тікетом, команда «запустити локально» додає
вкладку з dev-сервером, команда «прибрати» закриває групу.

Лише macOS + Google Chrome.

## Чому розширення

Групи вкладок Chrome доступні тільки через API розширень `chrome.tabGroups`:
AppleScript їх не бачить, а в DevTools Protocol такого домену немає. Тому
групування живе в невеликому розпакованому розширенні.

CLI дістається до нього без жодного демона: Chrome приймає URL-и
`chrome-extension://` від `open`, тому `task-tab` відкриває власну сторінку
керування розширення з параметрами в запиті. Ця сторінка виконує операцію й
закривається сама. Ні native messaging host, ні локального сервера. Єдине, що
працює у фоні, — синхронізація статусів.

## Панель QA-чекліста

Розширення несе ще один невеликий необов'язковий віджет: панель чекліста, що
плаває над сторінкою `localhost`. Вона з'являється, коли локальний QA-сервер
працює на порті `47823`, і зникає, коли він не працює.

Від цього сервера вона очікує три ендпоінти:

| Запит | Відповідь |
| --- | --- |
| `GET /api/qa/state` | `200` з `{ task, cases, discrepancies }` або `404`, коли жодна сесія не запущена |
| `POST /api/qa/case/:id` — `{"passed": true}` та/або `{"comment": "…"}`, обидва необов'язкові, але потрібен хоча б один (інакше `400`) | `204` |
| `POST /api/qa/finish` — `{"note": "…"}` | `200 {"ok": true}` |

Кейс — це `{ id, title, steps, expectedResult, area, status, passed, comment }`,
де `status` — одне з `new`, `updated`, `unchanged`, `outdated`; застарілий кейс
показано перекресленим, а не прихованим. Розбіжність — це
`{ id, summary, source, implemented }`, і її показано лише для читання.

До кожного кейса можна дописати довільний коментар: його набирають у панелі, і
він іде на сервер просто під час набору. Сервер тримає його поруч із тим кейсом і
повертає в наступному стані, тож на наступному рендері панель показує те, що є на
сервері.

Панель належить задачі тієї групи вкладок, у якій сидить її вкладка: коли
відкрито кілька задач одночасно, чекліст однієї задачі ніколи не з'явиться над
застосунком іншої, а вкладка без групи не показує нічого й не робить запитів.

Віддавати ці дані — не справа розширення: воно тільки клієнт. Якщо на порті ніхто
не слухає, панель просто не з'являється, а решта розширення працює як завжди.

Коли панелі немає, а ви хочете знати чому, переведіть фільтр рівня в консолі
сторінки на **Verbose**: там віджет розповідає про себе — чи завантажився його
content script, яку задачу він визначив для вкладки і чи відповів сервер. На
типовому рівні він мовчить, бо в більшості задач жодного сервера чекліста не
запускають, а віджет не має переказувати своє безділля в чужу консоль.

## Сервер за цією панеллю

Панель — лише клієнт. Розширення не постачає сервера: чекліст приходить від того,
хто слухає `47823` на машині самого розробника. Якщо там нікого немає, панель не
з'являється, а решта розширення працює так, ніби її й не існує: ні помилки, ні
заглушки, ні рядка в консолі на типовому рівні.

Це також означає, що ніхто не зобов'язаний користуватися саме тим сервером, який
стоїть за нею зараз. Свій власний може написати будь-хто — будь-якою мовою, за
один вечір — і панель його підхопить. Що саме вона від нього вимагає, описано в
[docs/qa-server-contract.md](./docs/qa-server-contract.md): маршрути, поля, які з
них необов'язкові, що віджет робить із відповіддю, якої не розпізнає, і кілька
обіцянок, яких сервер має дотримуватися.


## Встановлення

```bash
git clone https://github.com/vladimirfriptu/ttabs.git ~/ttabs && cd ~/ttabs
./install.sh
```

Перший запуск робить симлінки `task-tab` і `task-color` у `~/.local/bin` і на
цьому зупиняється, бо Chrome ще не бачив розширення. Завантажте його —
`chrome://extensions` → **Developer mode** → **Load unpacked** → виберіть каталог
`extension/` цього репозиторію — і запустіть `./install.sh` ще раз. Він визначить
id, який призначив Chrome, збереже його й запитає ваш сайт Jira:

```
Jira site
  URL (e.g. https://acme.atlassian.net), empty to skip: https://acme.atlassian.net
```

Задати або змінити його можна й потім: `task-tab site https://acme.atlassian.net`.
Під час першої синхронізації Chrome попросить доступ до цього хоста.

Запускайте `./install.sh` знову щоразу, коли розширення завантажують з іншого
каталогу: Chrome виводить id розпакованого розширення з його шляху, тому
переміщення репозиторію змінює id.

Шляхи — усі можна перевизначити змінною середовища:

| Що | Типово | Перевизначення |
|---|---|---|
| Симлінки CLI | `~/.local/bin` | `TASK_TABS_BIN` |
| Стан (`extension-id`, `colors/`) | `~/.local/share/task-tabs` | `TASK_TABS_HOME`, `XDG_DATA_HOME` |

## Використання

```bash
task-tab add ACME-1234 https://acme.atlassian.net/browse/ACME-1234
task-tab add ACME-1234 http://localhost:3000        # same group, second tab
task-tab --focus add ACME-1234 http://localhost:3000  # ...and jump to it
task-tab collapse ACME-1234                         # fold it up
task-tab close ACME-1234                            # close every tab in it
task-tab site https://acme.atlassian.net            # point the sync at your Jira
```

Додавання URL, який уже є в групі, нічого не робить замість того, щоб відкрити
дублікат. `task-tab` узагалі навмисно тихо не робить нічого: коли він не може
виконати роботу, він завершується з кодом 0 і без виводу, тож скрипт може
викликати його без жодних перевірок.

### Ніщо не краде у вас фокус

Вкладки впорядковуються у фоні. `open -g` не дає Chrome вийти на передній план,
нові вкладки створюються неактивними, а сторінка керування — яку Chrome таки
робить активною на ті ~200 мс, поки вона існує — перед тим, як закритися,
повертає вибір на ту вкладку, яку ви читали. Service worker тримає цю вкладку
окремо для кожного вікна й не зважає на сторінки керування, тож відповідь
правильна навіть після кількох команд підряд.

`--focus` вимикає це для того одного випадку, коли ви таки хочете, щоб вас
перенесло на вкладку.

## Префікс статусу

Service worker оновлює назву кожної групи кожні п'ять хвилин, на старті браузера
і відразу після `task-tab add`. Він збирає ключі задач із самих груп вкладок,
одним JQL-запитом питає в Jira їхні статуси й переписує лише ті назви, що
змінилися.

Автентифікація — ваша звичайна сесія в браузері: `fetch` із
`credentials: 'include'`. Жодного токена нікуди не зберігається. Поки сесія
протермінована, синхронізація тихо не вдається, і назви просто перестають
рухатися; достатньо відкрити Jira у вкладці.

Типова відповідність — статус Jira, якого тут немає, все одно отримує префікс:
перші чотири літери його назви:

| Статус | Префікс | | Статус | Префікс |
|---|---|---|---|---|
| Backlog | `BL` | | In test | `QA` |
| Requirements | `REQ` | | Ready for release | `REL` |
| Ready | `RDY` | | On hold / Blocked | `HOLD` |
| Ready for dev / To Do | `RDEV` / `TODO` | | Closed / Done | `DONE` |
| In dev / In progress | `DEV` | | | |
| On review / In review | `REV` | | | |

Пристосувати це до іншого процесу — одна правка в `extension/lib/statuses.js`;
більше ніде назви статусів не відомі.

`Closed` — просто ще один префікс: група лишається відкритою, доки її не прибере
`task-tab close`.

### Назву, яку ви написали самі, ніколи не перезаписують

Синхронізація переписує назву лише тоді, коли це чистий ключ (`ACME-261`), одна з
її власних форм із префіксом (`DEV|ACME-261`) або точно той рядок, який вона
записала минулого разу — останнє й дозволяє далі оновлювати запасний префікс для
незіставленого статусу. Усе інше (`[1] ACME-261`, `⚠️ ACME-261`) — ваше, і такої
групи синхронізація більше не торкається. Перейменуйте назву назад на чистий
ключ, щоб віддати групу їй знову.

**Тримайте ключ у назві.** Це єдине правило, якого має дотримуватися
перейменування: саме за ключем кожна команда знаходить групу, а будь-які оздоби
навколо — з будь-якого боку, у будь-якій кількості — ігноруються.
`[2] ACME-261`, `ACME-261 [2]`, `ACME-261 (waiting on design)` і
`ACME-261-empty-state-fixes` — усе це досі належить до `ACME-261`, тому
`task-tab add`, `close` і `collapse` до них дістаються. Приберіть ключ
(`design work`) — і група стане невидимою для CLI: наступний `task-tab add`
побудує поруч другу групу, а не візьме цю. Якщо в назві два ключі, виграє той,
що лівіше.

## Колірна прив'язка

Якщо ваш термінальний мультиплексор підписує свої вкладки за задачами,
`task-color` дає обом сторонам один колір, на якому вони сходяться:

```bash
task-color ACME-1234            # -> "purple 🟪"
task-color --chrome ACME-1234   # -> "purple"      (used by task-tab)
task-color --emoji  ACME-1234   # -> "🟪"          (for a terminal tab label)
task-color --set red ACME-1234  # override, remembered like any assignment
task-color --release ACME-1234  # return it to the pool
```

Колір обирається на першому виклику з тих, яких не тримає жодна інша жива задача,
і зберігається у `<state>/colors/<key>` — цей файл водночас і пам'ять, і список
зайнятого. `task-tab close` звільняє його, тож завершені задачі повертають свій
колір.

Але задача закінчується не лише так: закрийте групу вручну, видаліть worktree,
перезавантажте машину — і резервація трималася б назавжди. CLI не може спитати в
Chrome, які групи ще існують, тому кожне читання позначає резервацію як живу, а
задача, яка не знаходить нічого вільного, забирає той колір, про який найдовше
ніхто не питав — найімовірніше вже завершений. Тому кольори повторюються лише
тоді, коли ви справді маєте більше ніж шість задач у роботі, і сховище ніколи не
виростає більше за палітру.

Палітра — це шість кольорів груп вкладок Chrome, які мають суцільний
квадрат-емодзі: blue, green, purple, yellow, red, grey — саме в цьому порядку,
тож grey лишається на крайній випадок. Pink і cyan із Chrome пропущені: їхні
квадрати з Unicode 15 і в терміналах відображаються по-різному.

## Розробка

```bash
npm test        # node:test over extension/lib, plus task-color end to end
```

Розширення — це звичайні ES-модулі (`"type": "module"` для service worker і
`<script type="module">` на сторінці керування), тому немає ні кроку збірки, ні
бандлера: правите файл і натискаєте *Reload* на картці розширення в
`chrome://extensions`. Усе під `extension/lib/` не має жодних браузерних API —
саме це тести імпортують напряму.

Файли:

| Шлях | Роль |
|---|---|
| `bin/task-tab` | CLI: відкриває сторінку керування із запитаною дією |
| `bin/task-color` | CLI: призначає й запам'ятовує колір задачі |
| `bin/lib/common.sh` | Спільне для обох CLI та інсталятора: каталог стану, кодування URL |
| `extension/control.js` | Виконує одну дію на завантаження сторінки, тоді закриває вкладку |
| `extension/sync.js` | Service worker: планує синхронізацію і зв'язує повідомлення |
| `extension/lib/statuses.js` | Відповідність статус → префікс, і більше нічого |
| `extension/lib/titles.js` | Формат назви, виділення ключа, правило власності на назву |
| `extension/lib/plan.js` | Вирішує, які назви переписати — чиста логіка, без браузерних API |
| `extension/chrome/` | Тонкі обгортки над `chrome.*`: групи, фокус, сховище |
| `extension/providers/jira.js` | Єдиний файл, який знає API Jira |
| `install.sh` | Робить симлінки CLI, визначає id розширення, задає сайт Jira |

### Як націлити його на інший трекер

`extension/providers/jira.js` — це вся зв'язність. Сусідній файл, який експортує
той самий `fetchStatuses(site, keys) -> { key: statusName }`, плюс один рядок
імпорту в `sync.js` і новий хост у `manifest.json` — і це вся зміна; `lib/` і
`chrome/` про неї так і не дізнаються.

## Коли вкладки перестають з'являтися

`task-tab` навмисно падає тихо, тому починайте звідси, за спаданням імовірності:

1. **Id застарів.** Репозиторій переїхав або розширення завантажили з іншого
   каталогу. Запустіть `./install.sh` знову.
2. **Розширення вимкнули.** Chrome періодично пропонує вимкнути розширення в
   режимі розробника, і легко погодитися на автоматі. Перевірте
   `chrome://extensions`.
3. **Немає `extension-id`.** `ls ~/.local/share/task-tabs/extension-id`. Якщо
   файлу немає, запустіть `./install.sh`.

Щоб побачити, що зробив би CLI, виконайте його рядок `open` вручну: сторінка
керування пише помилки у свою консоль — `chrome://extensions` →
*Inspect views*.

## Коли префікс статусу перестає рухатися

Синхронізація теж мовчазна. Відкрийте `chrome://extensions` →
*Inspect views: service worker*: невдалий запуск пише туди
`[task-tabs] sync failed:`.

1. **Сайт Jira не налаштовано.** Лог так і каже; запустіть `task-tab site <url>`.
2. **Сесія Jira протермінувалася.** Запит повертається з 401; відкрийте свою Jira
   у вкладці, і наступний тік усе виправить.
3. **Назва більше не наша.** Групу, перейменовану вручну, пропускають навмисно —
   див. вище.
4. **Service worker так і не запустився.** Після будь-яких правок під
   `extension/` натисніть *Reload* на картці в `chrome://extensions`.

## Відомі незручності

- Chrome бурчить про розширення в режимі розробника. Позбутися цього можна лише
  через публікацію у Web Store або корпоративну політику; стабільний Chrome
  відмовляється від CRX-файлів, установлених збоку.
- Сторінка керування близько 200 мс є справжньою вкладкою, поки не закриється
  сама. `task-tab` використовує `open -g`, тому вона не краде фокус і її легко не
  помітити — але вона видима.
- `host_permissions` покриває `*.atlassian.net`. Для самостійно розміщеної Jira
  потрібно додати її хост у `extension/manifest.json`.
